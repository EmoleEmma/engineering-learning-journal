## Problems

One of the main problems I encountered was understanding what happens when
the local repository and remote GitHub repository contain different commits.

I also encountered a real merge conflict while working with my engineering
learning journal.

The conflict occurred because changes existed on both the local and remote
versions of `README.md`.

## Solved

I investigated the conflict using Git's status and conflict information.

I identified the conflicting sections, reviewed both versions, removed the
conflict markers, kept the correct content, staged the resolved file, and
completed the merge.

I then pushed the resolved repository back to GitHub.

This helped me understand merge conflicts better than simply reading about
them.

## Biggest Lesson

My biggest lesson this week was that Git is not just a collection of commands.

The commands make more sense when I understand the workflow behind them:

**Working Directory → Staging Area → Commit → Remote Repository**

I also learned that Git problems are often solved by first understanding the
current state of the repository rather than immediately trying random commands.
