# Git & GitHub Learning

This folder contains my Git and GitHub learning notes, exercises, experiments, practical work, and engineering lessons as I build my software engineering foundation.

The goal is not simply to memorize Git commands. I want to understand version control well enough to manage projects, track changes, work with branches, collaborate with other developers, recover from mistakes, maintain clean project history, and use GitHub professionally.

Git and GitHub will be used throughout the rest of my engineering learning journey because future projects, documentation, collaboration, CI/CD, and DevSecOps work will depend on a reliable version-control workflow.

## Learning Approach

My Git and GitHub learning follows the Engineering Learning Journal cycle:

**Roadmap → Learn → Practice → Build → Test → Document → Review**

I use the Git and GitHub roadmap as the learning map. I use my primary Git and GitHub course as the main structured learning resource, while official documentation and supplementary resources are used when I need additional explanations or references.

The goal is not to simply finish a course or memorize commands. Each topic should be reinforced through actual Git repositories, commits, branches, pull requests, merge conflicts, experiments, and documentation.

A topic is not considered complete simply because I watched a lesson. I should be able to explain the concept, use the relevant commands myself, recover from mistakes, and demonstrate the workflow through real repository activity.

# AI Usage

AI may be used as a learning assistant, but not as a replacement for understanding.

Useful ways to use AI include:

- Asking for explanations of Git concepts
- Asking why a Git command produced a particular result
- Understanding merge conflicts
- Practicing Git scenarios
- Generating troubleshooting exercises
- Reviewing commit messages
- Explaining Git history
- Practicing interview questions
- Reviewing GitHub Actions workflows
- Explaining unfamiliar YAML
- Improving documentation

After using AI-generated commands or workflows, I should understand what the commands do and verify their effects in my own repository.

I will not blindly run destructive commands such as `git reset --hard` or `git push --force` without understanding their consequences.

I will also never put passwords, access tokens, private keys, or other sensitive credentials into AI prompts.
