# Git Branches

**Date:** September 27, 2026

## What I Learned

Today I learned how Git branches allow developers to work on different
features, fixes, or experiments without directly changing the main branch.

I learned about:

- Git branches
- The `main` branch
- Creating branches
- Switching branches
- Feature branches
- Branch naming
- Making changes on a branch
- Merging branches
- Deleting branches
- Fast-forward merges
- Merge commits

## What I Practiced

I created a feature branch from the `main` branch and made changes without
directly modifying the main branch.

I practiced switching between branches, checking the current branch, making
commits on a feature branch, and merging the completed work back into `main`.

I also practiced creating and deleting branches after completing the work.

## What I Understand

I now understand that a branch provides a separate line of development
within a Git repository.

Branches allow developers to isolate work such as a new feature or bug fix
before integrating it into the main branch.

I also understand the basic feature branch workflow:

**Create Branch → Make Changes → Commit → Merge → Delete Branch**

The exercise helped me understand why branches are useful in software
development.

Instead of making experimental or feature changes directly on `main`, I can
create a separate branch, work on the changes, test them, and then integrate
them into the main branch when they are ready.
